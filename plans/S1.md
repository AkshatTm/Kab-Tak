**Branch:** `slice/S1-data-core`

## Design calls this plan makes (SPEC/IMPLEMENTATION_PLAN are silent; recorded in T1)
1. `active_min` / `wall_min` are stored as **float minutes** (sessions are second-accurate). `estimate_min` stays an int.
2. A task belongs to the **study day of its `started_at`**, or of `created_at` if it never started (D4). `GET /tasks` without `date` means today's study day.
3. `GET /api/categories` and `GET /api/part-types` are added (read-only). A client can't send `category_id` / `part_type_id` without them. They are not in SPEC §3.3 today.
4. No `DELETE /tasks`. SPEC §3.3 has none and `events` is an append-only history; the plan's word "CRUD" means create/read/update here.
5. `stop` requires `outcome`. It is legal from `running` and `paused`, not from `ready`/`draft`.
6. Server clock and OS local timezone come from an injectable `Clock` (fake in tests). Default tz = `datetime.now().astimezone().tzinfo`.
7. FastAPI runs sync routes in a threadpool, so "only one running" (D6) is enforced by a `threading.Lock` around the start/resume check-and-write, inside the same DB transaction. `shortcut:` single-process sidecar only; upgrade if the backend ever runs with several workers.
8. A failed migration at startup **stops the app** (no half-migrated DB). The existing `test_health_reports_db_error` is rewritten to break `check()` instead of the DB URL.

**T3 Timer state machine** (`backend/app/timer/machine.py`) — pure, no DB, independent of T2
- Plain dataclasses: `Task(status, estimate_min, sessions: list[Span])`, `Span(start, end|None)`. Pure functions `start / pause / resume / stop(task, at)` return a new state or raise `InvalidTransition` / `InvalidAt`. `active_min(task)` = Σ closed spans (+ open span to `now`), `wall_min` = stop − first start.
- Rules: `draft` can't start (D7); `ready → running → paused ⇄ running → stopped`; `at` must be ≤ now and ≥ the open span's start (or the last span's end when paused/stopping from paused) (D5); sessions never overlap.
- **Tests first:**
  - `tests/test_machine.py` (table-driven): every (status, command) pair → expected status or error; `at` before the span start → `InvalidAt`; `at` in the future → `InvalidAt`; stop from paused keeps `active_min` unchanged and counts paused time in `wall_min`.
  - `tests/test_machine_props.py` (Hypothesis): random command + clock-advance sequences on up to 3 tasks ⇒ active ≤ wall on every stopped task, no two open spans across all tasks when driven through the single-running rule, spans of a task ordered and non-overlapping.

**T4 Services** (`backend/app/timer/service.py`, `backend/app/timer/studyday.py`, `backend/app/timer/clock.py`) — after T2 + T3
- `clock.py`: `Clock` protocol + `SystemClock`.
- `studyday.py`: `study_day(instant_utc, tz, day_starts_at) -> date` (D4).
- `service.py`: `create_task`, `update_task`, `get_task`, `list_tasks(date)`, `running_task`, `start/pause/resume/stop`. Loads rows → machine → persists sessions, `started_at`/`stopped_at`/`active_min`/`wall_min`, `status`; writes one `events` row per state change (`task_created|task_updated|task_started|task_paused|task_resumed|task_stopped`, payload has `at`). `start`/`resume` raise `AlreadyRunning(task_id)` when another task is `running` (D6) under the module lock. Creating with an estimate → `ready`, without → `draft`; setting an estimate on a draft → `ready` (D7).
- **Tests first:**
  - `tests/test_studyday.py`: with a fixed +05:30 tz and cutoff 04:00, local 03:59 → previous day, 04:00 → same day; midnight rollover; cutoff `00:00` degenerates to the calendar day.
